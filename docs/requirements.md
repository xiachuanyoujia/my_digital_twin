# 一阶段：需求分析

## 1. 项目概述

**my_digital_twin** 是一款实时人体姿态驱动的 3D 数字孪生游戏软件。通过摄像头实时捕捉人体动作，将姿态数据映射到 Blender 导出的 3D 模型上，实现真人与虚拟角色的实时同步。

## 2. 目标平台

| 平台 | 说明 |
|------|------|
| Windows 11 | 主力开发与运行平台，RTX 5060 Ti 16GB 提供 GPU 加速 |
| Android | 移动端支持，通过手机摄像头实现便携体验 |

## 3. 核心功能需求

### 3.1 摄像头实时采集
- 支持 Windows 摄像头（USB/内置）及 Android 摄像头
- 实时帧率 ≥ 30fps，目标 60fps
- 自动适配分辨率（720p/1080p）
- 支持多摄像头切换

### 3.2 人体姿态识别
- **全身骨骼关键点检测**：至少 33 个关键点（MediaPipe Pose Landmarks 标准）
- **实时计算**：单帧推理时间 < 16ms（保证 60fps 流水线）
- **多人支持**：主画面识别单人（可扩展至多人）
- **遮挡处理**：部分遮挡时保持合理的姿态推断

### 3.3 3D 模型实时渲染
- 支持 Blender 导出的 **glTF/GLB** 或 **FBX** 格式 3D 人体模型
- 模型骨骼（Rig/Armature）与姿态关键点的**实时映射**
- 人体平面移动 → 3D 模型场景中同步位移
- GPU 加速渲染（利用 RTX 5060 Ti）
- 目标渲染帧率 60fps

### 3.4 交互功能
- 启动/停止姿态追踪
- 切换 3D 模型/场景
- 录制与回放动作序列
- 调整模型位置/缩放/视角

## 4. 非功能需求

### 4.1 性能指标
| 指标 | 目标值 |
|------|--------|
| 端到端延迟 | < 50ms（摄像头到渲染） |
| 姿态检测帧率 | ≥ 30fps |
| 渲染帧率 | ≥ 60fps (Windows) / 30fps (Android) |
| 内存占用 | < 4GB |
| GPU 利用率 | 合理利用 RTX 5060 Ti 16GB |

### 4.2 可用性
- Windows 端提供独立可执行文件（.exe）
- Android 端提供 APK 安装包
- 友好的用户界面，一键启动追踪

### 4.3 扩展性
- 后端 FastAPI 独立部署，支持多客户端连接
- 模型与骨架映射可配置化
- 预留多人姿态识别接口

## 5. 系统架构概要

```
[摄像头] → [姿态检测引擎] → [骨骼数据] → [3D渲染引擎]
                ↕                      ↕
         [FastAPI 后端] ←→ [Unity/前端 3D 渲染]
```

- **采集层**：摄像头驱动，帧捕获
- **推理层**：姿态估计 AI 模型（MediaPipe / OpenCV）
- **传输层**：WebSocket 实时双向通信
- **渲染层**：3D 模型加载 + 骨骼动画 + 场景渲染
